## Summary

R49 establishes a parallel production migration boundary at `/$locale/console-foundation`. The existing canonical `/$locale/console/*` routes already serve real business screens and have E2E contracts, so replacing their Overview with a placeholder would have caused a production regression. The new boundary lets later screens move one at a time while every existing public, authentication, and Console URL remains unchanged.

The new `ConsoleShell` uses the production locale boundary, real Zustand session user, existing preference/theme Store, and existing design-system Button, Sheet, Dropdown, and Separator components. It contains only an Overview navigation item and an intentionally empty Overview route surface. No prototype data, mock interactions, local business state, or API call was copied.

The design-system `SidebarProvider` was deliberately not used because it writes a `sidebar_state` Cookie when toggled. Desktop collapse and mobile Sheet state are transient React UI state instead; E2E asserts that navigation does not create that Cookie. Existing `partokens-theme` behavior is reused rather than adding a new persistence key.

## Architecture Inspection

| Area | Existing production structure | R49 choice |
|---|---|---|
| Routing | Code-defined TanStack Router tree under `/$locale`; canonical Console already has eleven real route variants including detail routes | Add sibling `console-foundation` tree and preserve canonical Console tree unchanged |
| Authentication | `useSessionStore.resolve()` calls the existing current-user contract; anonymous users go to localized sign-in and `role >= 10` users go to `/channels` | Extract the existing logic into `AuthenticatedUserBoundary` and use it for both shells |
| Theme | `usePreferenceStore` owns `light`, `dark`, and `system`; `data-theme` and theme-color are applied centrally | Read and update the same Store; add only Tailwind semantic mappings for existing design-system tokens |
| Store | Zustand session and preference Stores; React Query owns server data in business screens | Use session identity and theme only; introduce no Store or business state |
| Layout | `LocaleBoundary` owns locale and the public `TopNav`; legacy Console owns its sidebar beneath that header | Mark the foundation shell as full-viewport so it owns its header/sidebar without stacking `TopNav` |
| Styling | Production imports `@partokens/design-system/tokens.css`; Tailwind did not scan design-system sources or map semantic token names | Add `@source`, dark variant, and semantic `@theme` aliases in production CSS; do not change design-system |

## Migration Checklist

For every screen migration:

- Add a typed child route and navigation item under `consoleFoundationRoute`; keep the canonical production route on `LegacyConsoleShell` until parity is proven.
- Connect only the existing API client, React Query keys, session data, and Stores used by the production screen. Do not carry prototype fixtures, timers, success simulations, or local business state.
- Preserve locale, authentication/admin routing, theme modes, loading/error/empty states, destructive confirmations, and server-side authorization behavior.
- Add desktop and mobile E2E for route activity, keyboard access, focus restoration, overflow, console errors, and mutations appropriate to the screen.
- Cut the canonical route to the new shell only after its focused tests and the full production suite pass; remove legacy routing in a later explicit closeout, not in the screen migration.

Recommended migration order:

| Order | Screen | Reason |
|---:|---|---|
| 1 | Overview | Establish the real data composition and replace the R49 placeholder |
| 2 | Analytics | Read-only aggregate data with limited mutation risk |
| 3 | Usage logs | Read-only filters/detail workflow and route-state coverage |
| 4 | API keys | First destructive CRUD screen after read paths are stable |
| 5 | Wallet | Payment/top-up boundary and compliance confirmations |
| 6 | Profile | Basic account mutation before sensitive settings |
| 7 | Security | Sensitive confirmation and credential/passkey flows |
| 8 | Connections | External identity/linking boundaries |
| 9 | Notifications | Account settings and sensitive request-handling options |
| 10 | Playground | Streaming, local conversation history, and detail routes |
| 11 | Image Studio | Largest specialized surface: credential confirmation, generation, and local assets |

## Risks And Next Boundary

- `console-foundation` is intentionally not linked from the public `TopNav`; it is an authenticated migration/acceptance boundary, not a second customer-facing Console entry.
- Two shells coexist temporarily. Route ownership must remain explicit so a future screen is not accidentally mounted in both trees with divergent behavior.
- The production `system` theme behavior applies the current media preference when the Store initializes or changes; live OS-theme change observation is an existing Store limitation and was not expanded in R49.
- Semantic Tailwind color mappings are global production CSS infrastructure. Full public/auth/Console E2E passed, but future design-system component additions should continue to run the same regression suite.
- Canonical URL cutover and legacy-shell removal are explicitly outside R49. R50 should start with Overview only and stop after canonical-equivalent behavior is verified inside the foundation boundary.

R49 stops here. The production test server remains available at `http://127.0.0.1:4174/`; design-lab remains on port 4180.
