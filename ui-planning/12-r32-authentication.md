# Partokens R3.2 认证页面原型

状态：页面族完成内部验收，等待产品评审  
评审入口：`http://127.0.0.1:4180/#signin`

## 1. 范围

本轮只在 `partokens-ui/apps/design-lab` 中实现高保真认证页面，不修改 `new-api/`、`new-api-docs-v1/`、正式 `apps/web`、Caddy 路由或生产发布配置。

已实现路由：

- `#signin`：用户名/邮箱和密码登录，GitHub、LinuxDO、Google OAuth，协议与政策同意门槛。
- `#signup`：用户名、邮箱、注册验证码、密码确认与同意门槛。
- `#verify-email`：会话级保留邮箱、验证码与重发。
- `#forgot-password`：防账户枚举的统一成功反馈。
- `#reset-password`：重置确认、一次性新密码展示和兼容剪贴板反馈。
- `#oauth-callback`：提供商验证、账户路由确认和进入用户工作区。
- `#auth-otp`：验证器代码与一次性备用码切换。

## 2. 设计结构

认证被组织为账户访问路径，而不是营销式分屏：

```text
Identity -> Session -> Workspace
```

- 左侧轨道只展示服务状态、访问路径、账户数据边界、本地记录边界和支持联系方式。
- 右侧是无卡片嵌套的单一认证任务，保持 R2.1 输入框与按钮尺寸。
- `Route Capsule` 只用于登录、注册、验证、重置和进入工作区等确定性主行动。
- 820px 以下先展示认证任务，再展示账户与本地数据边界。
- OAuth 完成态在固定容器内替换加载态，不因状态变化改变主布局。

## 3. 产品与接口边界

- 邮箱验证码只用于注册和账户绑定，不提供邮箱验证码登录。
- 原型只演示状态与路由；正式实现仍由 New API 认证、会话、2FA 和角色字段决定结果。
- 普通用户进入独立用户工作区；角色 `>= 10` 在正式接入后硬跳转原生新版管理路径。
- 注册邮箱和 OAuth 提供商仅保存在 `sessionStorage`；主题和语言使用已有统一持久化键。
- 密码、OAuth 凭证和验证码不写入本地持久化存储。

## 4. 国际化与无障碍

- 简体中文、繁体中文、英语、日语、俄语、法语和越南语均有认证专用文案。
- 所有输入有可读标签，并使用 `username`、`current-password`、`new-password`、`email` 和 `one-time-code` 自动完成语义。
- 密码不一致使用 `role="alert"`，发送、拷贝和 OAuth 结果使用实时状态语义。
- 键盘焦点使用 R2.1 的 2px Relay Blue 轮廓；动效遵守 `prefers-reduced-motion`。

## 5. 评审重点

1. 认证页是否已经具有产品工作区的辨识度，而不像营销页或通用 Bootstrap 表单。
2. 信息密度、输入框与主按钮尺寸是否可以用于正式页面。
3. 账户数据与本地对话边界是否表达清楚。
4. 注册、密码恢复、OAuth 和 2FA 的流程是否适合进入正式表现层重建。
5. 七语言认证文案是否可以进入负责人审核。
