# Partokens R3.5 对话页面族原型

状态：页面族完成内部验收，等待产品评审  
评审入口：`http://127.0.0.1:4180/#console-playground`

## 1. 范围

本轮只在 `partokens-ui/apps/design-lab` 中实现高保真 Playground，不修改 `new-api/`、`new-api-docs-v1/`、正式 `apps/web`、Caddy 路由或生产发布配置。

已实现：

- 浏览器本地多会话、新建、选择、重命名、搜索、删除和清空。
- 连续对话流、消息复制、编辑后重新生成、删除、停止和重新生成。
- 模型、分组、流式开关、Temperature、Top P、最大 Token、惩罚项和 Seed。
- IndexedDB 存储用量、JSON 导入导出和破坏性操作确认。
- 桌面对话轨和移动端历史抽屉。
- 七语言、明暗主题和统一控制台壳层。

本阶段使用模拟回答验证表现和状态，不向生产模型发送请求。

## 2. 信息结构与视觉模式

```text
控制台侧栏
└── 游乐场
    ├── 本地会话轨
    │   ├── 新对话
    │   ├── 搜索
    │   ├── 今天 / 过去 7 天
    │   └── 本地数据
    └── 对话工作区
        ├── 会话名称 / 模型 / 分组 / 参数
        ├── Message Route
        ├── 连续消息流
        └── 输入区
```

- 页面使用完整高度工作区，不把消息做成聊天气泡，也不使用嵌套卡片网格。
- 会话轨强调高频切换与扫描；移动端由工具栏历史按钮打开带焦点约束的抽屉。
- `Message Route` 是本页的特征结构，依次显示“本机 IndexedDB -> Partokens Gateway -> 所选模型”。它将持久化边界和消息传输边界分开表达。
- 用户消息与模型回答使用连续文档流、细分隔线和回答侧色带，适合中等密度的长内容阅读。
- 页面复用 R2.1 tokens、按钮、输入、开关、对话框、反馈和 R3.3 控制台壳层，没有创建独立视觉系统。
- 移动端底部导航为概览、游乐场、API 密钥、钱包和菜单。

## 3. 本地数据模型

原型使用 Dexie/IndexedDB 存储会话，并以用户命名空间隔离。正式实现继续采用 `ownerNamespace = user:<id>`，不在不同用户间复用会话。

```text
LocalConversation
├── id / ownerNamespace
├── title / createdAt / updatedAt
├── model / group / parameters
├── messages[]
└── schemaVersion
```

- 首次打开设计原型时注入示例会话；独立初始化元数据确保用户清空后刷新不会重新注入。
- 新建空会话后立即发送的首条消息同步写入当前状态和 IndexedDB，不依赖 React 状态提交时序。
- 刷新时将遗留的 `streaming` 消息归一为 `stopped`，保留已生成内容和重新生成入口。
- 导入时重建会话/消息 ID、改写当前用户命名空间，并将导入的 `streaming` 状态归一为 `stopped`。
- 清空仅影响当前命名空间，且需要二次确认；导入导出不声称存在服务器同步。
- 页面持续显示：“对话记录仅保存在当前浏览器中。Partokens 不会存储你的对话记录。”

## 4. 关键交互

- 新建会话、首条消息自动命名、会话标题失焦保存和刷新恢复。
- 搜索无结果时显示明确空态；当前阶段不增加全文消息搜索。
- 模拟流式回答支持停止、刷新中断恢复、单条重新生成和编辑用户消息后截断后续内容重新生成。
- 参数对话框保存到当前会话；模型和分组变化同步更新 `Message Route`。
- 本地数据面板显示会话数、JSON 大小和存储位置，并提供导出、导入和清空。
- 会话、消息和全部数据均使用明确的破坏性确认；抽屉切换到确认对话框时先关闭抽屉，避免叠加两个模态层。
- 对话框支持初始焦点、Tab 循环、Escape、背景滚动锁定和关闭后的焦点恢复。

## 5. 产品与接口边界

- 正式消息请求使用 `POST /pg/chat/completions`，由 Cookie 会话建立临时 Playground token 上下文；用户不需要创建或展示 API 密钥。
- 模型选项来自 `GET /api/user/models?group=`，分组选项与倍率来自 `GET /api/user/self/groups`。
- 多会话、名称、搜索、参数记忆、导入导出和保留策略均为前端 IndexedDB 能力，没有服务器会话接口。
- “Partokens 不存储对话记录”只描述会话历史持久化；用户提交的消息仍会经 Partokens Gateway 发送给所选模型提供商。
- 正式接入必须保留流式解析、中止控制器、错误消息、会话过期和额度/权限错误；本原型的定时模拟不替代这些能力。
- 模型列表、分组和回答内容均为原型数据，不代表线上可用模型或实时响应。

## 6. 国际化、响应式与无障碍

- 简体中文、繁体中文、英语、日语、俄语、法语和越南语均覆盖本页自定义文案。
- 通用词条来自 `@partokens/i18n`；R3.5 独有词条暂存于 `console-playground-copy.ts`，等待负责人审核后再并入正式资源。
- 1440、1024、768、390 和 320px 均无页面级横向滚动；`Message Route` 在窄屏内部横向浏览，不扩大页面宽度。
- 法语 390px 和俄语 320px 暗色基准已检查长标签、工具栏、消息操作、输入区和底部导航。
- 图标按钮有可读名称和 tooltip；动态状态使用可读文本，消息流使用 `aria-live`。
- 移动历史抽屉和所有确认面只有一个活动模态层，并保持键盘焦点约束。
- 语言与主题使用统一持久化键，刷新后保留选择。

## 7. 评审重点

1. 本地会话轨与连续消息流的中等密度是否适合长期使用。
2. `Message Route` 是否清楚地区分本地历史、Partokens 传输和模型提供商。
3. “本地保存”披露是否足够醒目但不过度干扰聊天。
4. 桌面对话轨和移动历史抽屉是否符合预期。
5. 参数入口、消息操作和本地数据管理是否需要进一步收敛。
6. 页面族通过评审后，R3.6 是否按独立画布、密钥确认和本地项目进入生图工作台原型。
