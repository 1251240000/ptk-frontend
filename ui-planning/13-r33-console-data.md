# Partokens R3.3 控制台数据页面原型

状态：页面族完成内部验收，等待产品评审  
评审入口：`http://127.0.0.1:4180/#console`

## 1. 范围

本轮只在 `partokens-ui/apps/design-lab` 中实现高保真控制台数据页面，不修改 `new-api/`、`new-api-docs-v1/`、正式 `apps/web`、Caddy 路由或生产发布配置。

已实现路由：

- `#console`：账户就绪状态、余额与用量、服务状态、请求路径和近期消费。
- `#console-analytics`：时间、粒度和指标筛选，趋势、模型排行、密钥与模型流向，以及图表数据表。
- `#console-keys`：搜索、状态筛选、列管理、创建、编辑、启停、显式确认显示、复制、单项与批量删除。
- `#console-logs`：请求 ID、类型、模型、时间、分组和密钥筛选，混合事件列表、汇总与详情抽屉。

任务日志保持从普通用户导航中移除。钱包、资料、安全和通知设置进入 R3.4 账户页面族。

## 2. 信息结构

四个页面按用户要回答的问题分工：

```text
概览：账户是否已经可以发起请求
数据看板：用量发生在哪里
API 密钥：谁可以调用
使用日志：追踪一次请求或账户事件
```

- 顶部导航负责跨产品区域切换，侧栏负责控制台任务。
- 左下角固定展示余额和 30 天用量；移动端改用五项底部导航和完整侧栏抽屉。
- `Request Route` 将客户端、兼容端点、提供商路由和结果连接起来，作为数据页面族的识别元素。
- 页面保持中等密度，避免嵌套卡片；指标条、筛选条、表格和抽屉使用连续表面与明确分隔线。

## 3. 产品与接口边界

- 当前金额、用量、密钥和日志均为明确的原型数据，不代表线上账户。
- 概览和数据看板正式接入使用 `/api/user/self`、`/api/data/self`、`/api/data/flow/self`、`/api/uptime/status` 和可选性能指标接口。
- 密钥列表与 mutation 使用 `/api/token/*`；完整密钥默认隐藏，只在用户明确确认后调用单密钥显示接口。
- 使用日志使用 `/api/log/self`、`/api/log/self/stat` 和搜索接口，并允许登录、系统和错误事件缺少模型、Token 或费用字段。
- 正式实现继续通过兼容层校验响应、容忍可选字段和功能关闭，不直接在页面中请求原始接口。

## 4. 国际化、响应式与无障碍

- 简体中文、繁体中文、英语、日语、俄语、法语和越南语均已覆盖本页面族使用的文案。
- R3.3 专用新增词条保留在 `console-data-copy.ts`，负责人审核后再并入正式共享资源。
- 1440、1024、768、390 和 320px 均不产生页面级横向滚动；宽表格在 820px 以下转换为字段式记录。
- 移动侧栏、密钥对话框、密钥抽屉和日志详情均支持初始焦点、Tab 循环、Escape 关闭和焦点恢复。
- 图表提供可展开的数据表；图标按钮有可读名称；删除和完整密钥显示均有明确确认。
- 语言与主题使用统一持久化键，刷新后保持当前选择。

## 5. 评审重点

1. 概览是否能快速回答“账户是否可以发起请求”，而不是重复数据看板。
2. 数据看板的趋势、排行和流向三种视图是否足以进入正式实现。
3. 密钥默认隐藏、确认显示和批量操作是否符合安全预期。
4. 混合使用/登录/系统/错误事件是否适合放在同一日志页面。
5. 桌面中等密度与移动字段式记录是否适合长期使用。
6. 统一控制台壳层是否可以继续承载 R3.4 账户、R3.5 对话和 R3.6 生图页面族。
