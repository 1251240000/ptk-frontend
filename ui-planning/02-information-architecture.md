# Information Architecture And Flows

## Route Ownership

Canonical standalone user routes (`:locale` is one of `zh-CN`, `zh-TW`, `en`, `ja`, `ru`, `fr`, or `vi`):

| Area | Routes |
| --- | --- |
| Public | `/:locale/`, `/:locale/models`, `/:locale/docs/*`, `/:locale/about` |
| Legal | `/:locale/legal/user-agreement`, `/:locale/legal/service-agreement`, `/:locale/legal/privacy-policy` |
| Authentication | `/:locale/auth/sign-in`, `/:locale/auth/sign-up`, `/:locale/auth/forgot-password`, `/:locale/auth/reset`, `/:locale/auth/otp` |
| Console | `/:locale/console/overview`, `/:locale/console/analytics`, `/:locale/console/playground/:chatId?`, `/:locale/console/studio/:projectId?`, `/:locale/console/keys`, `/:locale/console/usage-logs`, `/:locale/console/wallet`, `/:locale/console/profile` |
| Technical entry | `/oauth/:provider`, `/user/reset` |
| Official admin entry | `/channels` |

Official New API management route ownership:

- `/channels`
- `/models/*`
- `/users`
- `/redemption-codes`
- `/subscriptions`
- `/system-info`
- `/system-settings/*`

Locale prefixes make the new user experience fully independent without claiming New API's native routes. For example, the public model marketplace is `/zh-CN/models`, while unprefixed `/models/*` remains official management UI. The root `/` performs locale negotiation and enters the matching localized homepage.

`/oauth/:provider` remains unprefixed because current OAuth provider redirect URIs use that shape. `/user/reset` remains unprefixed because password-reset emails generated by the current backend point there. Both entries render the standalone shell, restore the saved locale, and continue to the localized flow. They are technical compatibility entries, not public canonical pages.

## Global Navigation

Desktop top bar is 56 px high, fixed, and visually quiet. It contains the Partokens brand at left, primary public destinations in the center, and notice/language/theme/user controls at right. Global search is not included in P0.

Authenticated pages add a 216 px sidebar below the top bar. Sidebar groups are stable and not user-configurable.

Mobile uses:

- A 52 px top bar.
- Primary destinations in a bottom navigation: Overview, Playground, Studio, Wallet, More.
- "More" opens the complete navigation sheet.
- Tables use compact row summaries with a detail sheet.

## Sign-In

Desktop layout:

```text
┌───────────────────────┬──────────────────────────────────────┐
│ Partokens             │ Sign in                              │
│ live service status   │ username/email                       │
│ and support contact   │ password                    forgot    │
│ no promotional copy   │ [Sign in]                            │
│                       │ ───────── or continue with ─────────  │
│                       │ [GitHub] [LinuxDO] [Google]           │
│                       │ □ I agree to linked legal documents  │
└───────────────────────┴──────────────────────────────────────┘
```

Rules:

- Do not render an email-code sign-in mode. Email verification belongs on registration and binding flows.
- OAuth buttons remain clickable as soon as legal consent is checked; they do not depend on password fields.
- Do not duplicate legal consent in a second language below the checkbox.
- Preserve `redirect` only when it resolves to an allowed same-origin route.
- After final auth step, fetch `/api/user/self`; role `>= 10` hard-navigates to unprefixed `/channels`, otherwise to a validated same-locale return path or `/:locale/console/overview`.

## Registration

Registration visibility and required fields come from `/api/status`. When email verification is required, the page collects email, sends the code through `/api/verification`, and submits it with `/api/user/register`. It preserves Turnstile, affiliate, password validation, legal consent, resend cooldown, and recoverable error states.

## Playground

Desktop structure:

```text
┌─ Conversations ──────┬───────────────────────────────────────┐
│ [+ New chat]         │ model / group / parameters           │
│ Search               ├───────────────────────────────────────┤
│ Today                │ conversation stream                   │
│  API cost analysis   │                                       │
│  Refactor example    │                                       │
│ Previous 7 days      │                                       │
│  Translation notes   ├───────────────────────────────────────┤
│                      │ attachments  prompt            send   │
└──────────────────────┴───────────────────────────────────────┘
```

Local data model:

```ts
type LocalConversation = {
  id: string
  ownerNamespace: string
  title: string
  createdAt: number
  updatedAt: number
  model: string
  group: string
  parameters: Record<string, unknown>
  messages: LocalMessage[]
  schemaVersion: number
}
```

Implementation rules:

- IndexedDB, not localStorage, for multi-chat payloads.
- `ownerNamespace` is derived from the authenticated user ID through a one-way namespace function; it is not displayed.
- Interrupted assistant messages are normalized on reload.
- Retention defaults to user-controlled local storage rather than silently deleting by age.
- Provide storage usage and destructive clear confirmation.
- No server sync claim.
- Keep the disclosure visible in conversation settings and first-use state: "Conversation history is stored only in this browser. Partokens does not store your conversation history."
- State separately that sent messages pass through the Partokens gateway and selected model provider for generation.

## Image Studio

The workbench is full-bleed beneath the global top bar, not placed inside a dashboard card.

```text
┌ Toolbar: select hand undo redo fit export project settings ┐
├──────────────┬──────────────────────────────┬───────────────┤
│ Projects /   │                              │ Properties     │
│ Assets       │       infinite canvas        │ Prompt         │
│              │       nodes and links        │ Model          │
│              │                              │ Size / Quality │
│              │                              │ [Generate]     │
├──────────────┴──────────────────────────────┴───────────────┤
│ local save state · selected key alias · latest cost/log     │
└──────────────────────────────────────────────────────────────┘
```

Key setup flow:

1. List user keys without revealing values.
2. Ask the user to select an existing image-capable key or create a dedicated finite-quota key.
3. After explicit user confirmation, reveal the selected key through the session-authenticated, rate-limited endpoint only for the active runtime. The current backend does not provide step-up verification for this action.
4. Hold it in memory and attach it to same-origin `/v1/images/*` requests.
5. Clear it on logout, tab close, explicit lock, and prolonged inactivity.

Canvas requests must use explicit nodes and visible parameters. A node enters queued, generating, complete, failed, or cancelled state without changing its dimensions and shifting the surrounding canvas.

## Analytics

Top filter bar stays visible while scrolling. Measures are a segmented control (Requests, Tokens, Cost). Chart types use icon buttons with tooltips. Trend, distribution, and ranking are tabs because they are alternate views of the same dataset.

Each chart has:

- Loading skeleton with fixed dimensions.
- Empty state that retains filters.
- Inline error with retry.
- Accessible text summary.
- Data table view.

## API Keys

Default columns prioritize Name, Status, Key suffix, Quota, Group, Models, Last used, Expiry, Actions. IP restrictions and creation time are available through column controls/detail view.

Create/edit is a side sheet so users keep table context. Key reveal is a short-lived dialog with copy and rotation guidance. Destructive actions identify the key by name, never by full secret.

## Usage Logs

Filters are progressive:

- Always visible: time, type, model, search.
- Expanded: group, key/token, latency, cost range when supported.

The default view is a dense table. On mobile, each row shows time, type, model, cost, and status; tapping opens full details.

## Documentation

The `/:locale/docs` experience provides:

- Base URL and authentication quick start.
- Create/copy a key.
- First cURL request.
- SDK configuration for common clients.
- Full API reference, endpoint details, examples, and generated schema content in the active locale.

All seven locale trees are launch requirements. The Partokens docs app imports a pinned, read-only source snapshot from `new-api-docs-v1` and maintains translated overlays without changing that upstream repository.

## Public And Legal Content

Homepage, About, User Agreement, Terms of Service, Privacy Policy, and notices are repository-owned localized content. They do not fetch administrator-configured HTML at runtime.

User Agreement and Terms of Service are separate documents. Simplified Chinese is the drafting source, each translation carries draft/review metadata, and product-owner review is required before publication.

## Notice Behavior

The navbar notice button displays the current localized notice manifest bundled with the standalone release. A local content/version hash suppresses the unread dot after viewing. It is not described as a message inbox and does not invent per-user server state.

## Standard Page States

Every data page implements:

- First load.
- Refreshing with stale data retained.
- Empty result.
- Filtered empty result.
- Partial response.
- Permission/feature disabled.
- Session expired.
- Network unavailable.
- Retryable server error.
- Mutation pending/success/failure.
