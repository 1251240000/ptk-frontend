# Partokens 重设计简报：AI 产品工作区

状态：方向已确认，R1 已通过，R2 内部验收完成  
确认日期：2026-07-21  
影响范围：本文件取代 `03-design-system.md` 中的视觉方向；产品范围、接口契约、安全边界和部署方案继续有效。

## 1. 已确认决策

| 议题 | 决策 |
| --- | --- |
| 品牌图形 | 保留现有 Partokens 图案；允许调整颜色、底色、留白和锁定组合 |
| 视觉方向 | AI 产品工作区（AI Product Workspace） |
| 首页任务 | 直接展示产品实景并让访客立即开始，不做长篇营销导览 |
| 控制台密度 | 中等密度，优先保证扫描、比较和重复操作效率 |
| 信息架构 | 允许调整导航分组、页面顺序和文案，功能和接口能力必须完整 |
| 匿名价格 | 生产环境不会开放 `/api/pricing`；访客态不得伪造模型价格或可用模型 |
| 设计交付 | 先交付独立、可点击的高保真原型，评审通过后再接入现有业务逻辑 |

## 2. 产品主题

主题：把对话、生图、API 接入和账户数据组织成一个可以立即开始的 AI 产品工作区。  
受众：个人开发者、AI 工具使用者和需要清晰掌握成本的小团队。  
单一任务：让用户迅速判断账户是否可用、下一步该做什么，并直接进入一次真实操作。

界面应当呈现以下气质：

- 有技术可信度，但不是传统运维后台。
- 有生成式 AI 产品的活力，但不使用黑底霓虹、发光渐变和装饰性粒子。
- 公共页面有品牌尺度，登录后的工作区保持克制和高效。
- 状态、价格、额度、密钥和使用记录可以被扫读，不依赖卡片堆叠。

## 3. 参考站点提炼

| 参考 | 借鉴 | 明确不采用 |
| --- | --- | --- |
| Buildin.AI | 大幅产品实景、清晰留白、首屏内的产品模式切换、简洁文案 | 过多药丸容器、装饰性背景线、通用型全能产品叙事 |
| BytePlus Lumina | 应用即首页、任务和模型入口始终可操作、创作工具的沉浸感 | 黑底霓虹、大促弹窗、过度标签化、视觉噪声 |
| Box | 强品牌尺度、真实产品证据、大图层次和明确的主次行动 | 渐变标题、企业营销长页、与 Partokens 无关的品牌装饰 |

综合结论：使用 Buildin 的留白和纵向内容节奏、Lumina 的直接操作、Box 的品牌自信。首屏不复制任何站点的构图，而是用 Partokens 的真实产品窗口说明用户登录后能做什么。

## 4. 标志性体验：真实产品窗口

真实产品窗口是首页和登录页对产品能力的直接证明，不是概念流程图：

```text
Hero value statement
        |
        v
Conversation workspace preview
        |
        +-- Chat
        +-- Image studio
        +-- API keys and usage
```

### 访客态

- 首页直接展示对话工作区实景和三条 Get started 入口。
- 展示 `/api/status` 能够证明的真实服务状态。
- 明确说明可用模型和价格只在登录后按账户权限加载。
- 不展示虚构的延迟、可用率、模型数量、价格或健康百分比。
- 主要行动是“立即使用”，次要行动是查看接入文档。

### 登录与控制台连续性

- 登录页左侧使用同一产品窗口展示对话、生图和 API 密钥三个真实去向，右侧保持扁平登录表单。
- 控制台本身就是产品，不再额外套产品展示框；概览使用数据带和有主次关系的工作区。
- Playground 和生图工作台分别以聊天流和画布作为视觉主体。

产品窗口是公共页面唯一允许明显表达品牌个性的界面构件。控制台和工具页保持安静，避免重复展示或装饰性线路。

## 5. 视觉系统

### 核心色板

浅色主题：

| 名称 | 色值 | 用途 |
| --- | --- | --- |
| Cloud | `#F4F6FA` | 页面背景和宽幅工作区 |
| Paper | `#FFFFFF` | 输入、菜单、浮层和必要的实体表面 |
| Ink | `#111318` | 主文字与高对比命令 |
| Exchange Blue | `#2E67F8` | 品牌、焦点和主要行动 |
| Route Mint | `#18A978` | 可用、已连接和成功路由 |
| Signal Coral | `#F0655B` | 重要提醒、异常和关键对比 |

深色主题：

| 名称 | 色值 | 用途 |
| --- | --- | --- |
| Carbon | `#101216` | 页面背景 |
| Graphite | `#191C22` | 工具面板和浮层 |
| Chalk | `#F3F5F7` | 主文字 |
| Exchange Blue | `#6C91FF` | 品牌、焦点和主要行动 |
| Route Mint | `#3ACB98` | 可用、已连接和成功路由 |
| Signal Coral | `#FF8178` | 重要提醒和异常 |

警告状态另使用可访问的琥珀色语义 token。图表颜色必须来自独立的数据色板，不把品牌蓝重复用于所有序列。

### 字体

- 展示与品牌标题：`Geologica Variable`，只用于首页标题、关键数字和少量章节标题。
- 正文和界面：`Source Sans 3`，覆盖拉丁、越南语和西里尔文字。
- 数据、密钥、代码和请求编号：`IBM Plex Mono`。
- 简体中文、繁体中文和日语：对应的 Noto Sans CJK 字体，使用与拉丁界面相近的字重和行高。

第一轮原型必须验证法语、俄语和中文长文本。任何字体在真实字形测试中不协调时，允许在设计系统冻结前替换。

### 几何与层级

- 页面以工作区、分栏、数据带和分隔线组织，不使用卡片网格填满页面。
- 普通控件圆角 6px，主要按钮和对话框不超过 8px。
- 不使用玻璃拟态、渐变背景、光斑、悬浮装饰球或大面积阴影。
- 阴影仅表示真正的层级变化，例如菜单、对话框和拖动中的画布节点。
- 数据页最大宽度允许到 1480px；创作工作台使用完整可用视口。
- 控制台保持中等密度：40px 控件、48-52px 表格行、稳定的 8px 间距节奏。

### 动效

品牌动效只用于产品窗口内的流式响应或真实状态到达，持续时间不超过 500ms。其他动效限制在 120-180ms，用于菜单、抽屉、选择和画布操作；`prefers-reduced-motion` 下只保留必要状态变化。

## 6. 关键页面构图

### 首页桌面

```text
┌ logo ───── 模型 / 文档 / 关于 ───── 状态 语言 主题  登录  控制台 ┐
│                                                                  │
│            Partokens                                             │
│          你的 AI 工作区，从调用到创作                              │
│                    [立即使用] [查看文档]                            │
│                                                                  │
│  ┌──────────────── 对话工作区，全宽真实产品实景 ────────────────┐ │
│  │ 新对话 | 登录后选择模型 | 流式响应 | 本地记录声明 | 服务状态    │ │
│  └──────────────────────────────────────────────────────────────┘ │
├──────────────── GET STARTED 标签在首屏底部可见 ──────────────────┤
```

首页标题不会占据整个首屏。对话产品窗口是第一视觉主体，并在不登录时提供诚实的受限状态。

### 登录桌面

```text
┌───────────────────────┬──────────────────────────────────────┐
│ logo                  │ 登录                                  │
│                       │ 用户名或邮箱                           │
│ 对话 / 生图 / API      │ 密码                         忘记密码   │
│ 真实服务状态            │ 同意协议                               │
│ 本地会话边界            │ [登录]                                 │
│                       │ GitHub / LinuxDO / Google              │
└───────────────────────┴──────────────────────────────────────┘
```

左侧只展示登录后真实可进入的工作区、可验证服务状态和本地数据边界，不放抽象流程图。表单保持扁平，OAuth、验证码和错误状态共享统一反馈模式。

### 控制台概览

```text
┌ logo / workspace ───── 搜索当前页 ───── 状态 通知 语言 主题 用户 ┐
├ sidebar ──────────────┬─────────────────────────────────────────┤
│ Playground            │ 早上好，用户         [创建密钥] [发起对话]│
│ Image studio          │ 余额 / 30天用量 / 请求 / 密钥状态 数据带  │
│ Overview              ├─────────────────────────────────────────┤
│ Analytics             │ 用量趋势               下一步行动           │
│ API keys              │ 最近请求               API 接入             │
│ Usage logs            │                                         │
│ Wallet / Profile      │                                         │
│                       │                                         │
│ fixed usage summary   │                                         │
└───────────────────────┴─────────────────────────────────────────┘
```

公共导航不再完整复制到控制台。Logo 可以回到首页，侧栏负责产品区域导航，顶栏只保留当前工作区需要的全局工具。

### 移动端

- 首页压缩产品窗口但保留真实对话内容，并在首屏底部露出 Get started 标签。
- 控制台使用底部导航：概览、对话、生图、钱包、更多。
- 控制台移动侧栏提供语言和主题入口，并固定展示余额和近期用量。
- 表格转换为信息行和详情抽屉，不缩小为不可读的桌面表格。
- 生图工作台保留全屏画布，项目与属性通过底部 sheet 切换。

## 7. 信息架构调整

### 公共导航

- Partokens Logo 直接承担“首页”，不重复显示首页文字。
- 主导航：模型广场、使用文档、关于。
- “控制台”是明确的主要行动；未登录时进入登录流程，已登录时进入概览。
- 通知、语言、主题和用户入口保持为紧凑工具，不与主导航竞争。

### 控制台导航

- Chat：Playground、生图工作台。
- Workspace：概览、数据看板、API 密钥、使用日志。
- Account：钱包、个人资料。
- 左下角持续展示余额和近期用量，不制作虚假的百分比进度。

现有路由可以保持稳定，页面标题和导航标签允许按七语言的自然表达调整。

## 8. 页面族规则

- 首页、关于和法律页：强调品牌排版与内容阅读，不套控制台面板。
- 模型广场：以比较列表和筛选工作区为主体；访客态清楚解释登录要求。
- 概览和数据看板：数据带 + 一到两个主要工作区，不使用四到八张同尺寸指标卡。
- API 密钥和日志：工具栏、表格、详情抽屉组成完整工作流。
- 钱包和资料：按任务分区，危险操作与日常设置在视觉和位置上隔离。
- Playground：三栏可收缩结构，聊天流是视觉主体。
- 生图工作台：画布是主体，工具栏、项目和属性都是可隐藏的工具层。
- 文档：独立阅读和 API 探索体验，与公共品牌一致但不复制营销页面。

## 9. 自我审查与修正

第一版构想试图用“模型交换台”解释后台路由，但用户无法从该概念直接理解产品价值。修订后首页按 Hero、Get started、功能介绍、价值关键词、FAQ 和联系信息形成连续阅读路径，并使用真实工作区替代流程图。

第二个风险是把首页的大标题和展示窗口复制到所有页面。现方案只在首页和登录页使用产品窗口；控制台直接以数据带、表格和工作区表达产品，不做营销式构图。

第三个风险是深色主题落入普通 AI 工具的黑底霓虹风格。深色主题使用中性炭黑、较低饱和度的品牌蓝和有限的状态色，不使用发光边框或高饱和渐变。

## 10. 第一轮原型验收条件

- 首页、登录、控制台概览在 1440x900 和 390x844 下均完整可用。
- 明暗主题都呈现同一品牌，不是简单反色。
- 首页在首屏直接出现可操作产品实景，下一段内容仍有可见提示。
- 俄语、法语和中文长文本不溢出、不遮挡关键控件。
- 控制台达到中等密度，没有卡片嵌套和大面积无意义留白。
- 产品窗口、登录去向和控制台下一步行动不依赖额外说明文字才能理解。
- 原型评审通过前，不替换现有生产页面，也不进入发布流程。
