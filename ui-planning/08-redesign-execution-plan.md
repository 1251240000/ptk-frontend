# Partokens 重设计执行计划

状态：R3.6 生图工作台页面族完成内部验收，等待产品评审  
前置简报：`07-redesign-brief.md`

## 总原则

- 暂停发布，当前实现仅作为功能和接口基线。
- 不修改 `new-api/` 或 `new-api-docs-v1/`。
- 不推翻已经验证的 API client、认证、安全、本地存储和接口契约。
- 先确认设计，再重建表现层；不在正式页面中试错视觉方向。
- 每个阶段必须有可见交付物和明确评审门槛。

## R0：方向确认

状态：完成。

交付物：

- 现有界面问题审计。
- 三个参考站点的借鉴与排除项。
- “AI 产品工作区”设计方向。
- 品牌图形、首页任务、密度、价格权限和原型形式确认。

## R1：独立可点击概念原型

状态：完成并经产品负责人确认。

原型放在独立的设计目录中，不加入生产构建、Caddy 路由或现有应用入口。

### 页面

1. 首页。
2. 登录页。
3. 控制台概览。

### 必须可交互的内容

- 首页产品窗口、Get started、功能介绍、FAQ 和联系信息。
- 访客态模型/价格受限状态和登录行动。
- 登录表单、协议勾选、OAuth 按钮和错误状态。
- 控制台侧栏展开/收起、主题切换、通知和用户菜单。
- 概览的下一步行动、最近请求和用量展示。
- 桌面和移动导航。

### 原型数据规则

- 明确标注为“设计原型”的数据可以用于交互演示。
- 不把原型数字描述为线上实时数据。
- 最终实现中，服务状态只使用 `/api/status` 能够证明的字段。
- 模型和价格在访客态始终显示登录限制；登录后才接入 `/api/pricing` 和用户模型接口。

### 评审门槛

产品负责人需要确认：

- 整体是否达到现代、成熟和有品牌辨识度的目标。
- 首页是否足够产品化并能立即行动。
- 控制台信息密度是否合适。
- 导航、色彩、字体和产品工作区交互是否可以进入系统化扩展。

未通过时只修改独立原型，不接入业务代码。

## R2：设计系统冻结

状态：R2.0 已被视觉评审否决；R2.1 已经产品负责人确认并冻结。

交付物：

- 浅色和深色语义 tokens。
- 七语言字体栈和字号/行高规范。
- 间距、布局、圆角、边框、阴影和动效规范。
- 按钮、输入、选择器、菜单、标签、状态、表格、抽屉、对话框和反馈组件。
- 图表数据色板和可访问替代表格。
- 1440、1024、768、390 和 320px 的响应式规则。
- 键盘、焦点、reduced motion 和 WCAG 2.1 AA 验收清单。
- `Route Capsule` 主要命令、柔和填充次命令与工作流色带。

## R3：全页面高保真原型

状态：进行中。R3.1 公共与内容页面族已经确认；R3.2 认证、R3.3 控制台数据、R3.4 账户页面族、R3.5 对话页面族和 R3.6 生图工作台页面族已完成内部验收。R3.6 在统一控制台壳层内补齐本地项目、节点画布、生成路径、会话密钥边界、模拟生成状态和移动工具层，并通过七语言、明暗主题、关键工作流与 1440 至 320px 响应式验收。

按照页面族扩展，不按单个路由零散设计：

1. 公共与内容：首页、模型广场、文档、关于、法律、通知。
2. 认证：登录、注册、邮件验证、找回密码、重置、OAuth 回调、2FA。
3. 控制台数据：概览、数据看板、API 密钥、使用日志。
4. 账户：钱包、资料、安全、绑定和通知设置。
5. 对话：会话列表、聊天、参数、流式状态和本地数据管理。
6. 生图：画布、项目、节点、生成、密钥解锁和移动端工具层。

每个页面族至少提供桌面浅色和移动深色基准；高风险页面补齐四种组合。

## R4：表现层重建

### Wave 1：基础

- 新 tokens、字体和基础组件。
- 将 `@partokens/design-system` 建成 web/docs 的单一视觉依赖，页面不得复制基础控件样式。
- 公共导航、控制台 shell、移动导航、主题与国际化布局。
- 不继续复用现有全局 `styles.css` 的视觉规则。

### Wave 2：公共与认证

- 首页、模型广场、文档入口、关于、法律。
- 登录、注册、密码重置、OAuth 和 2FA。

### Wave 3：控制台数据与账户

- 概览、数据看板、密钥、日志、钱包和资料。
- 保留现有请求、mutation、安全确认和 E2E 契约。

### Wave 4：创作工具

- Playground。
- 生图工作台。
- 对本地存储、密钥内存边界和画布持久化执行专项回归。

每一 Wave 完成后都必须可单独验收，不等待所有页面完成后再统一发现视觉问题。

## R5：系统验收

- 七语言文案完整性和长文本视觉回归。
- 浅色、深色和系统主题。
- 桌面、平板和移动端关键流程。
- 键盘、焦点、屏幕阅读器语义和 reduced motion。
- 公共页面性能、路由级拆包和字体加载。
- 认证、角色跳转、钱包金额、密钥安全、本地聊天和生图密钥边界。
- New API 上游兼容检查、Caddy 路由所有权和完整 E2E。

## 明确不进入当前阶段的事项

- 生产发布和部署切换。
- AGPL 对应源码发布。
- 生产 OAuth、邮件和支付操作。
- 修改 New API 管理后台。
- 为匿名用户伪造或代理模型价格。

## 当前下一步

由产品负责人评审 R3.6 生图工作台页面族：`#console-studio`。确认后完成 R3 页面族总体验收并决定是否进入 R4 表现层重建。R1/R2/R3 评审产物继续保持独立，不进入正式 `apps/web`、Caddy 发布路由或生产发布流程。
