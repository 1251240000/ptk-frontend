# Partokens R3.4 账户页面族原型

状态：页面族完成内部验收，等待产品评审  
评审入口：`http://127.0.0.1:4180/#console-wallet`

## 1. 范围

本轮只在 `partokens-ui/apps/design-lab` 中实现高保真账户页面，不修改 `new-api/`、`new-api-docs-v1/`、正式 `apps/web`、Caddy 路由或生产发布配置。

已实现路由：

- `#console-wallet`：余额、用量、订阅扣费偏好、固定金额充值、兑换码、邀请奖励和账单记录。
- `#console-profile`：显示名称、用户名、绑定邮箱和每日签到，不展示用户 ID。
- `#console-security`：密码、2FA、Passkey、系统访问令牌和删除账户。
- `#console-connections`：邮箱、GitHub、LinuxDO 和 Google/OIDC 连接状态。
- `#console-notifications`：通知渠道、余额预警、未配置价格模型权限和请求 IP 日志设置。

控制台侧栏的“个人”分组仍只包含钱包和个人资料。安全、账号连接和通知设置使用个人资料页内的横向任务标签，不恢复原界面的左侧个人设置菜单。

## 2. 信息结构与视觉模式

```text
控制台侧栏
├── 钱包
└── 个人资料
    ├── 资料
    ├── 安全
    ├── 账号连接
    └── 通知设置
```

- 钱包的 `Balance Route` 将固定金额、折扣、预计支付和到账后余额连接起来，用户在支付前可以检查完整路径。
- 充值只显示后端 `amount_options` 配置的金额，原型没有自定义金额输入，也不从客户端生成金额。
- 个人资料页面族共用 `Account Trust` 轨迹，集中呈现身份、恢复邮箱、2FA 和 Passkey 状态。
- 页面沿用 R2.1 tokens、R3.3 控制台壳层、中等密度、连续表面和分隔线；没有新增 Bootstrap 式卡片网格或另一套按钮/输入样式。
- 侧栏左下角继续固定展示余额和 30 天用量；移动端沿用五项底部导航与侧栏抽屉。

## 3. 关键交互

- 固定充值金额、折扣与预计支付联动；支付前进入带键盘焦点约束的确认对话框。
- 订阅扣费偏好、兑换码、奖励转余额和账单刷新提供完整原型反馈。
- 资料保存与每日签到可操作；页面未显示用户 ID。
- 2FA 需要验证码后启用；Passkey 有独立设备验证确认面。
- 系统访问令牌先确认后生成，完整值只在生成后显示并可复制。
- 删除账户需要密码和准确用户名，条件满足前永久删除按钮不可用。
- 邮箱与 OAuth 服务支持连接/断开原型状态；通知渠道会按 Email、Webhook、Bark 或 Gotify 切换字段。

## 4. 产品与接口边界

- 当前金额、订单、订阅、签到和安全状态均为明确的原型数据，不代表线上账户。
- 钱包正式接入使用 `/api/user/topup/info`、充值计算/支付接口、`/api/user/topup`、`/api/user/topup/self`、订阅接口、`/api/user/aff` 和 `/api/user/aff_transfer`。
- 正式页面必须把空 `amount_options` 视为充值不可用，不能退回自定义金额或客户端默认金额。
- 资料与设置使用 `GET/PUT /api/user/self` 和 `PUT /api/user/setting`；签到使用 `/api/user/checkin`。
- 账号连接使用邮箱绑定与 `/api/user/oauth/bindings/*`；安全设置使用 `/api/user/2fa/*`、`/api/user/passkey/*`、`GET /api/user/token` 和账户删除接口。
- 正式实现继续通过 API client 和兼容层接入，不在页面中直接请求原始接口；现有错误、Turnstile、支付跳转和 WebAuthn 边界必须保留。

## 5. 国际化、响应式与无障碍

- 简体中文、繁体中文、英语、日语、俄语、法语和越南语均已覆盖本页面族文案。
- 复用 `@partokens/i18n` 的钱包与账户词条；R3.4 独有的设计标签暂存于 `console-account-copy.ts`，等待负责人审核后再并入正式资源。
- 1440、1024、768、390 和 320px 均无页面级横向滚动；钱包路径、账户保护轨迹、表单和账单表会按宽度重排。
- 充值、2FA、Passkey、令牌和删除确认支持初始焦点、Tab 循环、Escape 关闭、背景滚动锁定和焦点恢复。
- 图标按钮有可读名称，开关暴露 `role=switch` 与状态，充值金额使用单选语义。
- 语言与主题继续使用统一持久化键，刷新后保留当前选择。

## 6. 评审重点

1. `Balance Route` 是否比普通金额卡片更清楚地表达优惠、支付和到账关系。
2. 钱包信息密度是否适合长期查看订阅、充值、奖励与账单。
3. “侧栏只保留钱包/个人资料，其他设置用横向标签”是否符合预期。
4. `Account Trust` 是否能帮助用户发现 2FA 和 Passkey，而不制造安全分数焦虑。
5. 安全操作的确认层级是否充分，系统访问令牌是否仍需要进一步弱化入口。
6. 页面族通过评审后，R3.5 是否按本地多会话、参数和流式状态进入对话页原型。
